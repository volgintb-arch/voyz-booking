# Журнал решений

Решения владельца продукта. Новое решение — новая запись снизу, старые не правим.

## D-001 · 2026-10-07 · Приём предоплаты — поэтапно

- **Сейчас:** гость платит на QR или счёт хозяина (ELQR, MBANK, перевод).
  Хозяин подтверждает в приложении кнопкой «деньги пришли».
- **К сезону 2027:** онлайн-оплата через Freedom Pay KG по договору
  **каждого хозяина** (карты Visa/Mastercard/Элкарт, кошельки, MBANK,
  Optima24); оплата подтверждается автоматически.
- Деньги **никогда не идут через платформу** — иначе нужна лицензия
  платёжного агента НБКР.

## D-002 · 2026-10-07 · Комиссию за онлайн-оплату платит хозяин

Хозяин закладывает её в цену. Гость видит одну сумму, без доплаты на
последнем шаге.

## D-003 · 2026-10-07 · Регистрация иностранцев — модуль по желанию

Выключен по умолчанию. Паспортные данные собираются только у хозяина,
который сам включил модуль. Остальные — минимум данных гостя (имя,
телефон). Перед запуском модуля — консультация юриста по закону КР о
персональных данных.

## D-004 · 2026-10-07 · Сообщения на старте — бесплатные каналы

- Гостю: кнопка «написать в WhatsApp» / Telegram с готовым текстом.
- Хозяину: Telegram-бот (новая бронь с кнопками «Подтвердить» /
  «Отклонить», утренняя сводка заездов) и push в приложении.
- WhatsApp Business API (платный) — позже, когда будет поток броней.

## D-005 · 2026-10-08 · Сервер — в этом же репозитории

Папка `server/`. Секретов в коде нет: ключи, пароли и токены — только в
переменных окружения на сервере (`server/.env.example` — список).

## D-006 · 2026-10-08 · Хостинг: сначала пилот, потом Кыргызстан

- Пилот и показы — облачный хостинг (Render или аналог), только тестовые данные.
- Живой сезон — VPS в Кыргызстане (закон о персональных данных).
- Сервер собирается в Docker, поэтому переезд — смена адреса и переменных.

## D-007 · 2026-10-08 · Вход хозяина — через Telegram

Приложение показывает кнопку «Войти через Telegram», бот подтверждает вход.
Тот же бот присылает новые брони с кнопками «Подтвердить» / «Отклонить» /
«Деньги пришли» и утреннюю сводку. Гостю аккаунт не нужен: доступ к брони —
по секретной ссылке, сохранённой на его телефоне.

## Технические решения (без бизнес-последствий)

- Node.js 22 + Fastify + PostgreSQL 16, без ORM: SQL-миграции в `server/migrations`.
- Двойная продажа запрещена на уровне базы (ограничение `bookings_no_overlap`),
  плюс блокировка объекта на время создания брони.
- Цены, занятость и правила считает общий код `src/domain` — одинаково в
  приложении и на сервере.
- Фоновые задачи (Aynes, снятие неоплаченных броней, iCal, утренняя сводка)
  работают в том же процессе — для пилота хватает одного сервера.
